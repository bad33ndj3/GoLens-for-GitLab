# GoLens redesign — status

Five living visual references in this folder (all IntelliJ/GoLand-flavored, Darcula-ish token
colors). Open any of them directly in a browser — each has a fixed top-right nav linking to the
other four. None are wired into the extension — the real files listed per section still run the
old design/flow.

- `popover-demo.html` — the Go Intelligence hover/click popover (hand-tuned by the user, most
  mature).
- `settings-demo.html` — the settings page (`settings.html` + `settings.css`), first-pass
  conversion, not yet fine-tuned.
- `onboarding-demo.html` — the onboarding dialogs (`page/features/onboarding.internal.js`:
  quick-setup wizard + quick tour), first-pass conversion, not yet fine-tuned.
- `controls-demo.html` — the review-controls strip + bookmark drawer (`page/features/controls.js`),
  first-pass conversion, not yet fine-tuned.
- `project-search-demo.html` — the full-project-search modal (`page/features/project-search.js`),
  first-pass conversion, also replaces its old thick `.loading-progress` bar with the same
  spinner+count pill pattern already accepted in the popover header.

All demos beyond the popover were generated by Haiku subagents from the production markup,
reusing the popover's `:root` tokens and `.tok-*`/`.symbol-*` color logic. They are rougher than
the popover demo — expect a finetuning pass before they're considered settled.

**Shared tokens:** all five files now `<link rel="stylesheet" href="tokens.css">` instead of each
carrying its own copy-pasted `:root` block. `tokens.css` is the single source of truth for colors,
spacing, radii, shadows, motion — edit it once, all demos pick it up. It's a superset of what any
one file used before (adds `--golens-text-inverse`, `--golens-accent-warning`, `--golens-error`/
`--golens-warning` aliases that `controls-demo.html` needed).

**First finetuning pass (post design-review), applied across files:**
- Active-tab affordance unified: settings-sidebar's left-accent-border-in-info-blue pattern is now
  also used for onboarding's tour-nav tabs (previously a different full-border + primary-orange
  treatment). Blue is now consistently "this nav item is selected"; orange stays reserved for
  primary actions/CTAs and brand eyebrows.
- Row hover added where it was missing: `.shortcut-row`, `.host-item` (settings-demo.html),
  `.bookmark-item` (controls-demo.html) now highlight on hover like every other list row does.
- Destructive actions styled consistently: controls-demo.html's bookmark-drawer footer
  ("Clear current/stale/all") now uses the same red-outline treatment as settings-demo.html's
  `.destructive-action` — previously these irreversible actions looked like neutral buttons.
- `onboarding-demo.html` gained `<kbd>` styling (was relying on unstyled browser default) and
  `:active` press feedback on `.btn`/`.keymap-card`, both already present elsewhere.
- `settings-demo.html`: removed a hardcoded `#1d2126` (now `var(--golens-text-inverse)`), and
  replaced the `.shortcut-row` bottom-border removal hack (`:nth-last-child(-n+2)`, which silently
  broke if the shortcut count ever became odd) with a correct `:nth-child(even)`-only rule.

**Not yet done from that review (deferred, not started):** icon viewBox/stroke-width audit (user
said icons look fine for now, revisit later), and filling in missing interactive states (settings'
cache-progress bar and GitLab-origin form have no error/loading state shown in the demo yet).

**Second finetuning pass (designer review):**
- `:focus-visible` was defined globally in settings-demo.html/controls-demo.html but missing
  entirely in popover-demo.html, onboarding-demo.html, project-search-demo.html — keyboard
  navigation had no visible focus indicator on those three. Added, matching the existing
  `outline: 2px solid var(--golens-accent-focus)` convention.
- `onboarding-demo.html`'s `.keymap-card.selected` still used primary-orange for "this option is
  selected" — missed in the first pass's blue-for-selection rule. Now matches
  `.tour-tab.active`/`.settings-tab[aria-selected]`/`.choice:hover` (info-blue inset accent).
- `onboarding-demo.html`'s `.btn-primary` hardcoded `color:#000` instead of the
  `--golens-text-inverse` token — same class of bug already fixed once in settings-demo.html,
  missed here.
- `project-search-demo.html`'s error state ("Indexing failed. Network timeout.") was rendered in
  muted gray, same as normal status text — an error a user could miss. Now uses `--golens-error`.
- `controls-demo.html`'s bookmark-drawer "Remove" button (deletes one bookmark) hovered with the
  same orange treatment as "Jump"/"Recover" (primary actions), reading as a CTA instead of a
  destructive one. Added an error-tinted hover state, distinct from but lighter-weight than the
  drawer-footer's always-red bulk-clear buttons (per-row delete shouldn't be red at rest, only
  on hover intent).

## Design states — popover-demo.html

1. Hover → resolved definition (func)
1a. Hover → resolved definition (struct)
1b. Hover, name resolves to several unrelated symbols (compact pick-list)
2. Cmd/Ctrl+click → usages list, loaded (IntelliJ "Find Usages"-style, grouped by file, scrollable)
3. Usages list while still indexing (spinner + provisional count, skeleton rows)
4. Click a usage → at definition, doc+signature dropped, implementations load (compact rows)

## Design states — settings-demo.html

Full settings page, sidebar + 5 tabs (General, Shortcuts, GitLab access, Cache, Help), all
wired up with working tab-switch JS in the demo itself. Sidebar tab accent changed from a filled
highlight background to a thin left-edge accent border (IntelliJ settings-dialog convention).
Preference rows, shortcut rows, host rows compacted to smaller single-line-first patterns.

## Design states — onboarding-demo.html

Three states shown stacked, not interactive:
1. Quick-setup step 1 — keymap choice cards, thin-border selection instead of filled block
2. Quick-setup step 3 — the four essentials, compacted to single-line rows with top-dividers
3. Quick-tour — left tab rail + "Go intelligence" chapter fully worked out with flat divided rows

## Design states — controls-demo.html

1. Controls strip at rest — all 5 buttons (toggle, focus, preload/cache, bookmarks, diff-view)
2. Controls strip busy — preload showing in-button progress fill + count, bookmark badge + stale dot
3. Bookmark drawer open — current-head list + stale-after-head-change list, compact flat rows

## Design states — project-search-demo.html

1. Indexing — the old thick `.loading-progress` block (phase + percentage + wide bar) replaced by
   a compact spinner+count pill, adapted for a modal header instead of a popover header
2. Error state — same layout with a Retry action and an inline error message
3. Minimized chip — small fixed floating element, plus a completed variant with a checkmark

## Not yet implemented in real code (biggest gap)

`code-intel.js` only implements the OLD flow: hover always shows docs+signature+scope+choices,
Cmd/Ctrl+click either jumps straight to a single definition or shows the old two-line ambiguous
picker. None of this is real yet:

- Usages-list popover (state 2/3): grouped-by-file rows, header usage count, scroll-triggered
  loading, skeleton rows. No DOM/markup, no JS, no data source for "all usages of X" exists.
- Dropping docs/signature once "at definition" (state 4) — `showResult()` always renders docs.
- Compact single-line choice rows (`.choice--compact`, `.choice-inline-path`) — real markup
  still uses the old two-line `.choice-heading` / `.choice-context` layout.
- Small header spinner+count pattern (`.usages-count.is-loading`) — real `showLoading()` still
  renders the full `.loading-progress` bar (phase label + percentage + progress track).
- Real syntax highlighting — `.tok-*` classes only exist as hand-tokenized HTML in the demo.
  Production `renderSignature()` / `choiceButton()` render plain text; there's no Go tokenizer
  to color dynamic signatures.
- Per-file destination icon (in-diff vs. new-tab) grouped at the file-header level — real code
  only has a per-choice destination icon, no file-grouping concept at all.

## Known inconsistencies — decided

- `code-intel.js` shortcut-hint text still says "go to definition"; demo says "find usages".
  **Decision: leave the real code as-is until Cmd/Ctrl+click actually finds usages** — don't
  promise behavior the UI doesn't deliver yet.
- `.choice-doc`, `.choice-heading`, `.choice-context`, `.choice-copy` CSS classes were unused
  dead weight in the demo (fully replaced by `.choice--compact`). **Removed** from the demo file.
  Real `code-intel.js` still needs these classes — it hasn't been ported to the compact layout.
- Two palettes coexist: `.symbol-*` badge colors (symbol-kind, VSCode-derived) vs. `.tok-*`
  signature/syntax colors (IntelliJ-derived). **Decision: keep both for now** (different job —
  kind-of-symbol vs. syntax-highlighting), but **the user wants to eventually pull the rest of
  the extension UI (not just this popover) into the new IntelliJ-derived design colors** — treat
  the popover's palette as the seed for a broader visual pass later, not a one-off.
- Declared type/struct names (e.g. `Msg`) intentionally use the *base* text color (`.tok-param`),
  not `.tok-type` — only *referenced* types are blue. Any future signature markup needs to follow
  this rule consistently or names will look randomly colored.

## Future scope (flagged by user, not started)

- Extend the IntelliJ-derived color language from this popover to the rest of the extension's
  UI surfaces (onboarding, settings, celebration — see the other `#golens-*-root` scopes in
  `golens-theme.css`), so the whole extension reads as one coherent design instead of just this
  one popover.

## Open design questions

- Real "usages" data: does GoLens have (or can it get) a full usages/references index, or only
  definition resolution today? This determines whether state 2/3 is buildable at all short-term.
- Scroll-triggered "load more" (state 3) needs a real pagination/streaming mechanism from
  whatever indexes usages — currently pure CSS/markup mockup.
- Recursive click-through (usage → definition → implementations, IntelliJ-style) needs a real
  navigation/history stack in the popover, not just a single fixed template.
